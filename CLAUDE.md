# HEARsay Mysteries — project notes for Claude

A Twine 2 / SugarCube 2.37.3 game that teaches Julia Minson's HEAR framework (Hedge, Emphasize agreement, Acknowledge, Reframe to the positive). This repository holds every scenario (so far one, *The Commons' Comma*) and the engine they share; GitHub Pages serves the games from `docs/`. Owner: Tomer Perry (GitHub: HolyTispoon).

## Sources of truth (in order)

1. The Google Doc "HEARsay mysteries" (above): the framework and rules. Read it; don't rely on older copies (`Archive/Hearsay Mystery Game.docx` and the claude.ai project's framework.md are superseded; the old PDF export has been removed).
2. Per scenario: the Response Matrix (`scenarios/<id>/… – Response Matrix.xlsx`), which the game is built from, and the Scenario Packet (`scenarios/<id>/… – Scenario Packet.docx`), which must say the same things. Both are edited by hand.
3. `engine/HEARsay game text.xlsx`: all of the engine's player-facing text and the framework's numbers (Facts sheet). `engine/hearsay_engine.twee` holds no wording.

Use the doc's names for the game's parts: Introduction, the Hook, the CCC, Clues, Red Herrings, Major Clues, tripwire, follow-up, budget, final-answer form; passages Start, Rules, the Hook, Map, Interview, Answer, Follow-up, Evidence Board, Submission, Result, ending, ranking. Don't invent other names.

Structural changes to the framework are the user's decisions and belong in the Google Doc first. Ask before making them in the game.

## Where things live

- `engine/`: the same for every scenario. The engine (`hearsay_engine.twee`), the game text workbook, the build and check scripts, `landing.html` (the site's landing page; its wording is edited there), `head.html` and the site icons.
- `scenarios/<Scenario ID>/`: one folder per scenario, named by the matrix's Scenario ID. The matrix, the packet, `assets/` (the portraits and map the game uses) and `source-art/` (originals, not used by the build).
- `docs/`: the published site, generated by the build. `index.html` is the landing page; `<id>/index.html` is each game, with its `assets/` and generated `source/story.twee`. Never edit anything in `docs/` by hand; rebuild.
- `ARCHITECTURE.md`: why the repository is laid out this way, and the migration steps still open.
- Google Drive folder "HEARsay mystery game" (owner tperry@g.harvard.edu): the framework Google Doc and its export, the Drive `CLAUDE.md` (project notes, open items and the Tweego/SugarCube paths on the user's Mac) and `Archive/`. The repository is cloned into that folder as `HEARsay-Mysteries/`, synced by Google Drive for desktop. Changes merged into `main` reach it only when the user runs `bash tools/update-drive.sh` on the Mac (it lists every file it would change and asks first); there is no scheduled pull, by the user's choice. Nothing is copied between the repository and Drive by hand. Don't leave that clone on another branch: do branch work in a separate clone. Drive still holds the old folders `Twine engine/` and `The Commons' Comma/` until they are archived (see `ARCHITECTURE.md`); don't update them.

## Build

Needs Python 3.8+ with `openpyxl`, `python-docx` (and `pypdf` for a PDF export), and Tweego 2.1+ pointed at SugarCube 2.37.3. From the repo root:

```
python3 engine/build.py --framework "<export of the Google Doc>.docx"                  # every scenario
python3 engine/build.py commons-comma --framework "<export of the Google Doc>.docx"    # one scenario
```

Checks run in order: game text vs. framework export, engine text keys; then per scenario matrix vs. Facts and itself, Scenario ID vs. folder name, packet vs. matrix, then Twee, Tweego, assets; then no two scenarios share an IFID, and the landing page. It fails loudly: fix the source, don't loosen a check. Without `--framework` it looks for a `HEARsay mysteries` export in the repository folder and the folder above it (in Drive, next to the Google Doc); if there is none the framework check is skipped with a warning. An engine or game-text change needs every scenario rebuilt; commit the rebuilt `docs/` with it.

In a cloud session, `.claude/hooks/session-start.sh` installs Tweego 2.1.1, SugarCube 2.37.3 and the Python packages and sets `TWEEGO` and `TWEEGO_PATH`. For the framework check, export the Google Doc as plain text through the Drive connector (`download_file_content` with `text/plain`) and pass the file with `--framework`.

## Pull requests

Push every commit as soon as it is made, and keep every pushed branch in an open pull request against `main`. Open it with the first push, following `.github/pull_request_template.md` (summary, questions for the author, follow-up needed to activate the work); when later commits change the picture, update its description. Keep the template consistent with the one in HolyTispoon/Ethics-Sandbox-Virtual-Tabletop: the shared sections are word for word the same, and that repo adds a build-plan pointer and a Checks list.

## Gotchas

- Don't run the docx skill's `merge_runs.py` on the packet (it once turned "=" into "."). Edit the packet's XML directly.
- Matrix columns are found by header name. 'Given by', 'Tripwire question', Grid and repeated set titles are copies the build checks; keep them in sync by hand.
- Game text cells are trimmed. `rules.N` rows display in number order.
- Regression test: the build is deterministic, so for a change that should not alter a game, build `main` and the branch and compare `docs/<id>/index.html` byte for byte. For a change that should, walk the same screens of both builds in iframes with `Math.random` stubbed and diff `innerText`.

## Engine choices not yet in the Google Doc

History/undo disabled so tripwires stick; follow-up bonus 1 point; ranking 1 per exact place, ½ per place off; follow-up phrasings in random order; the debrief reveals the solution, Major Clues and each red-herring set's resolution; Follow-up Result, Case File and Sidebar are engine additions. Open with the user: the doc puts the big reveal before the ranking, but players who answer wrongly get the full story only in the debrief after ranking; the HEAR guide paraphrases the doc's table.
